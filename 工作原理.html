Taichu 太初 · 沙箱生命周期: 创建 / 复用 / 续约

页面 2/4 · B5 横向 · 续约规则: 剩余 TTL ≤ min(阈值, 上限) 才续满全量 TTL
创建与复用流程 (RuntimeService 状态机)
① client 登录成功 → POST /runtime (X-User-Id, X-Tenant-Id)
② gateway 查 Redis: {prefix}:user:{userId} → snapshot
③ 命中可复用状态 (PENDING/CREATING/RUNNING/READY)?
是 → 复用: 续约判断 + INITIAL_STATE → 秒级 READY
否 → 新建: 落索引 PENDING → 后台创建 K8s Pod
④ 探活 /global/health (轮询, 超时判 FAILED) → READY → SSE 事件 → 返回 agentApiBase
客户端拿到 baseUrl → fs 通道 / OpenCode SDK / SSE 事件流全部就绪
续约机制 (有操作才续约)
触发路径① 所有走 runtime 的请求 (子域名 + /agent/*, RuntimeRoutingFilter#renewIfNeeded) ② POST /runtime 复用 (RuntimeService#reuseExisting)
Lua 原子续约 (RENEW_IF_LOW_LUA · 单次往返, 无竞态, 多副本共享)
① EXISTS {prefix}:renew-throttle:{runtimeId} ? → 命中 (5s 窗口内) 直接跳过
② PTTL 双索引剩余 → 剩余 ≤ min(renew-threshold-seconds, renew-threshold-max-seconds) ?
③ 是 → PEXPIRE 双 key 续满 ttl (600s); 否 → 不续约, 仅记录判断
④ SET 节流 key PX 5s → 下次判断最早在 5s 后 (节流状态存 Redis, 无内存表)
配置项 (gateway.runtime.*, ConfigMap 与 application.yml 同步) ttl = 600s (空闲 TTL, 续满目标)
renew-throttle-seconds = 5s (流量续约节流窗口, Redis 共享)
renew-threshold-seconds = 180s (续约阈值)
renew-threshold-max-seconds = 180s (阈值硬上限, 禁止代码硬编码)
生效阈值 = min(阈值, 上限); 活跃期剩余时间维持 3~10 分钟
页面 2/4 · 续约判断由 Lua 原子完成, 与流量节流合并为一次往返; 续约失败只告警不影响转发

续约规则

· 剩余 TTL ≤ min(阈值, 上限) → 续满 ttl
· 触发: 走 runtime 流量 (5s Redis 节流) + POST 复用
· Lua 原子, 无内存状态, 多副本共享

回收规则

· 判定: Redis 索引 key 过期 (存在性)
· 主链路: keyspace expired 事件实时回收
· 兜底: informer 巡检孤儿 (每 5min, 零轮询)

边界约束

· 回收只删 Deployment/Service, PVC 不删
· gateway 不渲染 UI / 不解析 A2UI
· registry 不参与运行时 / 沙箱不参与调度
实测验证记录 (2026-08-03, docker-desktop 单节点)

验证

· 回收链路: 10 个孤儿 pod (3 用户) → 部署回收后 30s 内自动清至仅活跃沙箱
· 增量续约: 双索引降 TTL 100s → 发请求 → 双 key 续满 599s
· 节流: 续满后 5s 窗口内再请求 → TTL 不动 (Redis 节流 key 生效)
· 阈值: 剩余 566s (>180s) 请求不续约, 符合规则

维护要点

· 改 TTL/续约/回收配置: ConfigMap + application.yml + redis.yaml 三处同步
· @Scheduled placeholder 一律带默认值, 防 ConfigMap 未同步启动失败
· 巡检禁止 list K8s API, 必须 informer 缓存
